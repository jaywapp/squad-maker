## Play 타겟 연령 안내

타겟 연령은 실제로 설계·홍보하는 사용자 범위이고 콘텐츠 등급은 별도 설문/등급 결과다. `16~17세`를 선택했다고 앱 등급이 자동으로 16세가 되는 것은 아니다. `18세 이상`만 선택하는 미성년자 접근 제한 방향은 이번 제품 대상과 맞지 않는다. [Google Play 한국어 안내](https://support.google.com/googleplay/android-developer/answer/9867159?hl=ko).

Google 안내는 16~17세도 일부 지역에서 아동으로 간주될 수 있다고 설명한다. 대상 지역·실제 콘텐츠·SDK 처리를 함께 확인하고 Families 적용 여부를 타겟 숫자만으로 확정하지 않는다. 한국만 출시한다는 Console 계획은 실제 사용자의 위치/연령 인증을 대신하지 않는다. 아동 대상 마케팅·전 연령 대상이라는 문구를 임의로 추가하지 않는다.

출시 전 Console에서는 한국어 등록정보와 실제 화면을 나란히 확인하고 타겟 `16~17세`, `18세 이상`, 별도 콘텐츠 등급 설문, 광고 포함 선언을 검토한다. Console 제출은 미실행이며 콘텐츠 등급도 미확정이다.

## 화면·문구 대조 결과

- 승인된 피치/Run Line/한글 A안은 유지한다. 조사한 현 화면·승인 브랜딩에 아동용·전 연령용이라는 주장을 발견하지 못했다. 이미지별 Play 심사 결과를 받은 것은 아니다.
- 도움말 앱 정보와 README에 실제 제품 대상을 반영했다. 메타 설명은 축구·풋살 선수·동호인·코치와 실제 배치/패턴/이미지·GIF·링크 공유 기능을 설명한다.
- 관심도 안내의 포괄적인 개인정보 미수집 표현을 팀·선수·전술 내용을 분석에 포함하지 않는다는 범위로 좁혔다. 광고 SDK가 처리하는 정보와 구분한다.
- 도움말에 공개 지원 이메일을 추가했다. 기존 코치 인터뷰 모집 주소, 제보자가 입력하는 연락처, GitHub Issue 중계 API는 서로 다른 역할이므로 일괄 치환하지 않았다. 원본/라이선스/과거 작성자 이메일도 보존했다.
- 스토어 설명 초안은 이번 문서에서 처음 준비했다. 실제 등록정보/스크린샷·선택 콘텐츠 등급·메일 수신은 미검증이다.

## 청소년 광고 보호 점검

현재 GMA25.5.0/UMP4.0.0을 사용한다. 매 실행 UMP 갱신, 필요한 폼, `canRequestAds`, 개인정보 옵션은 구현했다. `ConsentRequestConfiguration`은 UMP와 같은 build-time TFUA boolean을 GMA 요청에 전달한다. 그러나 이것만으로 16~17세 처리·개인화 보호·광고 콘텐츠 등급·개인정보 신고가 해결되는 것은 아니다.

| 설정 | 현재 상태 | 출시 전 처리 |
|---|---|---|
| UMP 동의/옵션 | 구현·합성/정책 unit 확인, 실제 폼 미검증 | 공개 정책과 계정 메시지·대상 지역·기기 폼 확인 |
| TFUA | 전달 구현, 운영 모드는 명시 값 요구 | TFUA false를 TEEN 보호라고 표현하지 않음. 제품 타겟만으로 사용자별 값을 추측하지 않음 |
| TEEN 연령 보호 | 실제 GMA25.5 enum/builder/getter 확인, 미구현 | 보호안 승인 후 연결·단위/빌드 검증 |
| 최대 광고 콘텐츠 등급 | 앱에서 미설정 | G 등급 제한 추천. 최종 콘텐츠 등급과 별개로 확인 |
| 비개인화 보호 | 앱에서 명시 정책 미설정 | 아래 보수적인 첫 출시안 승인 대기 |
| AdMob 차단/심사 | 계정 화면 미확인 | 청소년에게 부적절한 광고 범주·실제 설정·심사 확인. 실제 운영 광고 반복 노출/클릭 금지 |
| 연령 확인 | 없음 | 생년월일을 수집하거나 성인이라고 가정하지 않음 |

요청 설정 테스트에 있던 PG/개인화 비활성 값은 기존 설정을 보존하는 테스트 입력이며 실제 앱 설정 완료 증거가 아니었다. 운영 빌드 게이트는 닫혀 있어 실제 운영 광고는 요청하지 않았다.

**사용자에게 제안한 첫 출시안 — 답변 대기:** 연령/생년월일을 추가 수집하지 않고 성인을 포함한 모든 광고 요청에 TEEN 보호, 비개인화, G 등급 제한을 적용한다. UMP의 동의 연령 미만 신호 또는 더 강한 기존 CHILD 신호가 있으면 CHILD를 우선한다. 이는 사용자의 실제 연령 인증이나 모든 법적 의무 이행이라는 주장이 아니다. 연령별 개인화 분리는 별도 설계/결정으로 남긴다. 이번 질문은 로컬 구현만 대상으로 하며 운영 광고 노출·배포를 승인하지 않는다.

Google은 TEEN 처리에서 개인화·리마케팅 제한과 청소년 보호를 설명하며, 새 age treatment와 기존 TFUA/TFCD를 함께 지정하면 더 강한 신호를 적용한다고 안내한다. [AdMob 연령 처리](https://support.google.com/admob/answer/6219315?hl=en), [Android 요청 설정](https://developers.google.com/admob/android/targeting), [청소년 광고 보호](https://support.google.com/adspolicy/answer/12205906). TEEN만으로 식별자/IP/진단 전송이 모두 사라진다고 가정하지 않는다.
