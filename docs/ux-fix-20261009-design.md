# UX/UI 개선 1차 (2026-10-09): 설계

- slug: `ux-fix-20261009` · [분석](ux-fix-20261009-analysis.md) · [작업 지시서](ux-fix-20261009-tasks.md)
- 기준 설계: [A 운영 UI 설계](a-ui-20261007-design.md)의 토큰·컴포넌트를 그대로 쓴다. 새 토큰은 만들지 않는 것이 원칙이고, 불가피하면 이 문서에 이유를 남긴다.
- 행 번호는 점검 시점(aa89187 = 현재 `origin/main`의 `index.html`) 기준이다. 수정이 진행되면 밀리므로 셀렉터·함수명으로 찾는다.

## 1. 설계 원칙

1. **원인 하나를 고쳐 증상 여럿을 없앤다.** `body > *` 폭 규칙처럼 공통 원인이 있으면 개별 요소 덮어쓰기보다 원인을 고친다.
2. **선택 상태는 초크, 주 행동은 라임.** A 설계의 색 역할을 다시 지킨다(1단계는 선택 상태만, 화면별 라임 개수 정리는 2단계).
3. **파괴적 확인은 실행 버튼이 기본값이 아니다.** 라벨은 동사+대상, 초기 포커스는 취소.
4. **결과는 버튼 가까이에 남긴다.** 토스트는 보조이고, 성공·실패는 해당 패널의 결과 줄에 지속 표시한다.
5. **보이는 글자 = 접근성 이름의 앞부분.** 음성 제어와 스크린리더가 같은 이름을 쓰게 한다.

## 2. 변경 설계 (1단계)

### 2.1 fixed 레이어 폭 (B-01, B-16)

- `body > * { width: 100% }`에서 fixed 레이어를 제외한다. 우선안: `body > :not(.toast, #ctxMenu, .dlg-backdrop, .modal-overlay)`처럼 제외하거나, 레이아웃 대상에만 클래스로 적용. 실제 fixed 레이어 목록은 `body` 직계 자식 중 `position: fixed` 요소를 조사해 확정한다.
- `#ctxMenu`: `width: max-content; max-width: calc(100vw - 16px)`.
- `showCtxMenu()`: `innerWidth - 180` 가정을 버리고 표시 후 `offsetWidth/offsetHeight`로 화면 안으로 보정(좌우·상하 8px 여백).
- 메뉴 머리에 대상 선수 표시("7. 미드3"). 메뉴를 여는 순간 선택 상태(트레이)도 같은 선수로 맞춘다.
- `.toast`: `width: auto; max-width: min(560px, 100vw - 24px)`, 가운데 정렬.

### 2.2 확인 대화상자 `uiConfirm()` (B-05)

- 시그니처에 확인 라벨과 톤을 받는다(예: `uiConfirm(message, { confirmLabel, tone: 'danger' | 'default' })`). 기존 호출(2178·2328행 등)은 전부 동사 라벨로 바꾼다: "8vs8로 바꾸기", "배치 초기화", "백업으로 바꾸기".
- `tone: 'danger'`는 위험 스타일(Q4 결정: `--danger` 테두리, `--danger-ink` 글자, 라임 배경 금지).
- 초기 포커스는 "취소". 제목·본문은 `aria-labelledby`/`aria-describedby`로 연결하고 고정 `aria-label="변경 확인"`을 없앤다.
- 본문 줄바꿈은 2.5의 전역 `keep-all`로 해결.
- 호환성: 테스트(`data-safety`, `local-library`, `player-id-safety`, `ui-contract`, `guest-free-regression`)가 확인 버튼을 이름으로 찾는지 확인하고 새 라벨에 맞춘다.

### 2.3 제보 모달 (B-08)

- 전역 Esc 처리(3789행)에 `#feedbackModal` → `closeFeedback()` 추가. 다른 시트처럼 포커스 복귀 확인.
- 창구 준비 실패 상태에서는 "제보 보내기"를 `disabled` + `aria-disabled`로 하고 "다시 시도" 버튼을 둔다. 오류 문구는 열자마자가 아니라 준비 확인이 실패했을 때만 보인다(현재 동작이 그 경우라면 문구는 유지하고 버튼 상태만 맞춘다).

### 2.4 결과·상태 표시 (B-10, B-26, B-22, B-04)

- 복원 성공·실패·취소를 `.export-status`에 `data-tone="success|error|neutral"`로 쓰고 오류는 지속 표시. 이전 성공 문구가 남지 않게 매 시도 시작 시 비운다.
- "+ 선수 추가" 비활성 시 보조 문구 "9명 모두 배치됨"(인원 수 반영)을 버튼에 `aria-describedby`로 연결.
- 이름 입력에 "n/12" 카운터. 트레이 이름은 `title`로 전체 이름, 데스크톱 트레이는 두 줄까지 허용.
- 패턴 미리보기 재생 중 단계 이동 줄 라벨을 재생 단계와 같은 값으로 갱신하고 이전·다음을 잠근다(표시 출처 하나).

### 2.5 전역 CSS·토큰 (B-17, B-23, B-07, B-20/D-01, D-02, D-05, D-06, B-13 일부)

- `:root { color-scheme: dark; }`, `html { scrollbar-gutter: stable; }`. 내보내기 시트의 13px 넘침은 내부 여백 조정으로 없앤다.
- `body { word-break: keep-all; overflow-wrap: anywhere; }`. 763행 개별 규칙은 중복이면 정리.
- `.tactic-tag`: 텍스트 토큰 `--faint`를 바탕으로 쓰지 않는다. 역할별로 짙은 바탕 + 밝은 글자, 4.5:1 이상. GK 글자는 `--danger-ink`.
- 선수 번호 `#field .player-circle`: `font-weight: 700`(18.5px → 큰 글자 3:1 기준 충족). 패턴 캔버스는 2단계.
- "+ 선수 추가": opacity 겹침을 없애고 비활성은 토큰 색으로 표현해 4.5:1(비활성이라도 읽혀야 함) 이상.
- 11.2px 본문(detector D-05): 해당 요소를 찾아 A 설계의 최소 본문 크기(12px 이상)로 올린다.
- `width` transition(D-06): 해당 요소를 찾아 `transform`/`opacity` 기반으로 바꾼다. 찾지 못하면 Deferred.
- `.mode-pill.active`: 라임 → 초크(스쿼드 탭·앱 탭 활성과 같은 규칙).

### 2.6 접근성 의미 (B-18, B-19)

- 인원 버튼: `aria-pressed="true|false"`(생성부 1968행과 상태 변경 시 모두 갱신).
- 선수 토큰 접근성 이름: 보이는 글자로 시작("2 수비1, 선수 편집").
- 색상 견본: 16진 대신 색 이름 표(빨강·파랑·…)를 하나 두고 `aria-label="선수 색상 빨강"`.

### 2.7 문구 (B-09, B-21, B-25, B-24)

- 도움말: 실제 탭 이름(배치 / 움직임 패턴 / 매치 전략)과 버튼 이름(백업 파일 저장 (.sq) / 백업에서 복원), 모바일 주 경로(탭 → 하단 도구), 전술 목록·내보내기 시트 설명 추가. 첫 포커스는 제목 또는 닫기.
- 힌트: 모바일 "탭: 선수 도구 · 끌기: 이동". 데스크톱은 빈 상태 카드와 피치 아래 줄 중 한 곳만. "끌면 자리만 옮겨집니다"는 실제 동작(이동 후 그 선수 선택)에 맞게.
- em dash 제거: title/og 메타, "기본 스쿼드 — 전체 지침", 토스트 "복사됨 — …", 도움말, 피치 `aria-label`. 마침표·쉼표로 대체.
- 문자 글리프 "◀ ▶ ↺ ✕"를 이미 쓰는 Tabler 인라인 SVG(chevron-left/right, refresh, x)로 교체. 파비콘은 유지(Q3 결정).

## 3. 2단계: 움직임 패턴 화면 A 편입 (Q1 결정: 콘셉트 없이 진행)

### 3.1 패턴 캔버스 렌더 (B-03)

- `canvasPlayer()`(2942~2958행)가 DOM 피치와 같은 표현을 쓰게 한다.
  - 글꼴: 하드코딩 `Segoe UI` 대신 `getComputedStyle(document.documentElement)`에서 `--font`·`--num` 값을 읽어 쓴다(Oswald 번호).
  - 크기: 캔버스 표시 배율(`canvas.clientWidth / canvas.width`)을 구해 이름이 **화면 기준 12px 이상**, 번호가 DOM 피치와 비슷한 크기가 되도록 보정한다.
  - 이름표: 어두운 반투명 알약 바탕(DOM `#field .player-name`과 같은 색·반경). `slice(0,7)` 대신 폭 기준 말줄임표(`…`).
  - 골라인 근처(GK) 이름표는 DOM 피치처럼 토큰 옆으로 뺀다.
  - 토큰 지름 `PLAYER_R = 22`(1847행)는 390에서 약 33px다. A 기준(36px 이상)에 맞게 배율 보정 후 반지름을 올린다. 경로 그리기 히트 영역은 바꾸지 않는다.
- GIF 내보내기도 같은 렌더 함수를 쓰므로 결과물도 함께 바뀐다. GIF 한 장을 실제로 만들어 확인한다.

### 3.2 패턴 패널 정리 (B-14, B-13)

- 패턴 패널의 "GIF 저장 / 전체 패턴 GIF"를 없애고 내보내기 패널의 "현재 패턴 GIF 저장 / 전체 패턴 GIF 저장"만 남긴다. 분석 이벤트 이름은 바꾸지 않는다(내보내기 패널 경로가 같은 이벤트를 쓰는지 먼저 확인하고, 다르면 Deferred).
- 패턴 "삭제", "단계 초기화", "단계 삭제"는 패널 머리줄의 더보기(⋯, Tabler `dots`) 메뉴로 모은다. 파괴적 항목은 2.2의 `uiConfirm` 위험 톤을 쓴다.
- "고급 영상 (준비 중)" 칩은 실제 버튼 줄에서 빼 패널 맨 아래 "출시 예정" 묶음으로 옮긴다.
- 화면당 라임 1개: 움직임 패턴 화면은 "미리보기"를 보조(초크 테두리)로 내리고 "내보내기·공유"만 라임. 매치 전략 화면은 "전술 지침서 생성"을 보조로, "기본 스쿼드 · 8vs8" 칩은 초크.
- 지침서 선수명 `.tactic-player-title`은 `--warn` 대신 `--ink`, 역할 태그는 1단계 F-04 대비 기준을 유지한 작은 라벨로.
- 목표: 데스크톱 기준 패턴 패널에 동시에 보이는 버튼 13개 → 7개 이하.

### 3.3 재생 중 단계 표시 (B-04 잔여)

- 1단계 F-05에서 표시 출처를 하나로 맞췄다면 여기서는 재생 중 이전·다음 잠금과 "재생 중 n/N" 라벨만 확인한다.

### 3.4 구형 모달 A 시트화 (B-11)

- `#shareModal`(1460행), `#helpModal`(1539행), `#feedbackModal`(1592행)을 `#librarySheet`와 같은 머리줄(제목 + 오른쪽 위 X 아이콘 버튼 + 구분선) 구조로 바꾼다. 아래쪽 "닫기"·"✕ 닫기" 버튼은 없앤다.
- 포커스 트랩·Esc·포커스 복귀는 `SquadUi.closeTopLayer`(A UI U-03) 경로로 통일한다.
- 공유 모달 "파일 저장" → "텍스트 파일로 받기".
- `tests/unit/platform-native.test.js`의 모달·닫기 함수 매핑(`closeHelp`, `closeFeedback`)은 유지되게 한다.
- 웹 `navigator.share` 노출(B-11 권고 일부)은 기능 추가라 이번에 하지 않는다.

### 3.5 키보드 선수 이동 (B-15)

- 포커스한 `#field .player`에서 방향키: 8px, Shift+방향키: 32px 이동. 피치 경계에서 멈춘다. 이동 결과는 드래그와 같은 저장 경로(자동 저장·되돌리기)를 탄다.
- 이동 후 `aria-live="polite"` 영역에 "미드1, 왼쪽에서 30%, 위에서 45%"처럼 알린다.
- 패턴 캔버스: 캔버스 옆(모바일은 아래)에 단계별 텍스트 요약 목록("단계 1: 미드1 → 오른쪽 위로 이동")을 둔다. 캔버스 `tabindex=-1`은 유지하되 `aria-describedby`로 요약을 연결한다. 키보드 경로 그리기는 이번 범위가 아니다.
- 방향키가 페이지 스크롤과 충돌하지 않게 선수 포커스 상태에서만 `preventDefault`.

## 3A. 3단계: 구조 재설계 콘셉트 (Q2 결정: 콘셉트 3종)

- 위치: `docs/ux-concepts/ux-fix-20261009/concept-01`, `concept-02`, `concept-03`. 실행 가능한 HTML 프로토타입 + README(의도·트레이드오프·스크린샷).
- 세 콘셉트 모두 같은 세 문제를 푼다: (1) 모바일 가로 844×390에서 피치와 선택 도구가 함께 보임(B-02), (2) 1920 이상에서 설정 열이 좁아지지 않음(B-06, D-07), (3) PNG/GIF 결과물 헤더가 피치 선과 겹치지 않고 팀명이 드러남(B-12).
- 서로 실질적으로 다른 방향이어야 한다(레포 규칙: 레이아웃·타이포·모션이 달라야 하고 색만 바꾼 변형 금지). 출발점 예시:
  - 가로 2열 편집형: 가로에서 헤더를 한 줄로 접고 피치 | 도구 2열. 대형 화면은 3열(목록 | 피치 | 설정). 결과물은 상단 불투명 헤더 띠.
  - 몰입 피치형: 가로·대형 모두 피치를 최대화하고 도구는 떠 있는 레일·시트. 결과물은 피치 아래 캡션 띠.
  - 매치카드형: 대형 화면은 피치 + 라인업 카드 2단, 가로는 카드 접힘. 결과물은 경기 카드(팀명·포메이션·날짜) 템플릿.
- A 디자인 토큰을 공유하고, `impeccable`·`design-taste-frontend` pre-flight를 거친다. 데스크톱(1280·1920)·모바일(390, 844×390 에뮬레이션)·기본 접근성을 확인한다.
- 사용자에게 3종을 제시하고 선택·피드백을 이 slug의 분석 문서에 기록한다. **선택 전에는 `index.html`을 바꾸지 않는다.** 선택 후 운영 구현은 새 작업계획으로 연다.

## 4. 대안과 트레이드오프

- `body > *` 규칙 자체를 없애는 안: 레이아웃 전체가 흔들릴 위험이 커서 제외 목록 방식(2.1)을 택했다.
- 확인 버튼을 초크 보조 스타일로 하는 안: 시각 충돌은 적지만 위험 신호가 약하다. 위험 신호를 우선해 위험 스타일로 결정했다(Q4).
- 키보드 이동을 1단계에 넣는 안: 접근성 효과는 크지만 드래그·저장 로직과 엮이는 기능 추가라 2단계로 미뤘다.

## 5. 보안·호환성

- 저장 형식·계약 v2·분석 이벤트를 바꾸지 않는다. Android 번들은 같은 `index.html`을 쓰므로 `npm run android:bundle` 표식 확인을 회귀에 포함한다.
- 시크릿 관련 변경 없음.

## 6. 검증 전략

- 기준선 → 수정 → 회귀 순서는 [A UI 작업](a-ui-20261007-tasks.md)과 같다. 이 머신은 메모리가 적으므로 단위 → 데스크톱 e2e → 모바일 e2e를 포그라운드에서 `--workers=1`, 프로젝트별로 순차 실행한다.
- UX 재검증은 `ux-fix-20261009/browser.md`의 Repro를 그대로 재실행한다. 모바일은 리사이즈가 아니라 `390x844x3,mobile,touch` 에뮬레이션.
