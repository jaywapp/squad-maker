## 근거와 범위

`onModeChange`의 확인은 지침만 검사한다. `resetLayout`은 확인·undo 없이 현재 배치를 바꾼다. `loadSquadFile`은 복원 후 저장하지 않는다. `autoSave`는 저장 오류를 숨긴다. 외부 데이터 복원이 일부 값을 바꾼 뒤 실패할 수 있으며, 손상된 시작 데이터는 기본값으로 자동 덮일 수 있다. 이름 편집 확정도 저장 요청이 없다.

기존 v:1 fixture는 수정하지 않는다. 별도 보호 회귀는 한 번만 저장소를 seed하고 reload에서 재주입하지 않아 결함을 가리지 않는다. 이름/배치/패턴만 수정한 경우, 세 스쿼드, 취소·진행·undo·재시작, 저장 오류·재읽기 오류, 잘못된 입력·구형 패턴·지원 불가 버전을 검사한다.

## 결정과 가정

- 승인된 손실 보호 범위에서 인원 변경·현재 배치 초기화·파일 교체는 확인 후 실행한다. 취소는 원본·선택·저장본 무변경.
- 복구는 현재 세션의 가장 최근 보호 동작 한 단계다. reload를 넘는 삭제 복구/백업 정책 Q9는 확정하지 않는다. 진행과 undo 결과는 즉시 저장·재읽기 검증하며 저장 실패는 성공으로 표시하지 않는다.
- 인원 변경의 기존 기본 명단 생성 의미는 유지하되 이름·색상·세 배치·지침·모든 패턴 영향과 복구 범위를 안내한다. 초기화는 현재 스쿼드 배치만 변경한다.
- A UI·반응형·시각 개편은 Claude 전용. 이 작업의 `index.html` 편집 기간이 끝날 때까지 같은 파일은 순차 사용한다. 완료 SHA와 계약을 남기되 PR #41의 C-02/C-03 게이트를 임의 통과시키지 않는다.
- 서버·Supabase·Android 프레임워크·native adapter·팀/파일 보관·슬롯 수량·가격·광고·구매·APK 생성은 이번 범위가 아니다. 로컬 웹 데이터 보호이므로 Supabase가 필요 없다.
- 최종 목표인 설치 검증 APK의 GitHub Releases 공급은 T-01/Q6, A UI/통합·기기 검증·서명 승인 이후 별도 후속 작업이다.

## 완료 기준

재현한 결함의 회귀가 보호 구현에서 통과하고 기존 전체 웹 회귀와 PNG/GIF가 유지된다. UI에 제공하는 상태·revision·저장 결과·취소/오류·undo·export 계약과 정상/실패/빈/미구현 fixture를 버전으로 고정한다. 검증 SHA·파일 소유권·미완료 게이트를 draft PR에 남긴다.

## 구현·검토 결과

기준 소스에서 새 보호 9개 테스트가 모두 예상 실패했다. 기능 보호와 최소 계약 adapter를 단일 파일에 구현했고, 기존 .sq 왕복 회귀에는 교체 확인 클릭만 추가했다. 원본 fixture·A 자료·vendor·패키지/lockfile·배포/비밀값 설정은 변경하지 않았다.

독립 Codex 검토가 확인한 부분 복원·손상 시작 데이터 덮기·이름 확정 저장 누락·rollback 불확실 상태·출력 준비 timeout·모달 잠금·revision 알림 순서·패턴/단계 알림·큰 ID의 다음 할당 위험을 수정하고 회귀로 고정했다. 읽기 전용 검토를 부모가 코드와 실행 결과로 확인했다. 저장소 접근 원문이나 선수 데이터를 외부 진단에 넣지 않는다.

P0 보호는 기존 v:1 웹 상태와 runtime 한 단계 복구에 한정한다. rollback 검증 자체가 실패하면 원문 복구를 보장한다고 표시하지 않고 추가 저장을 차단한다. 확인 후 유효한 파일 가져오기만 차단 저장본을 교체한다. 운영 UI 인계 준비와 APK 공급은 PR #41의 후속 게이트를 유지한다.
