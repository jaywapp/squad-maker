# Play 실기기 검증·정책 확인 목록

현재 모든 항목은 **실기기 미검증**이다. 로컬 fake의 통과로 완료 처리하지 않는다. 앱 설치·서명·트랙 업로드는 별도 승인 후 진행한다.

## 필요한 조건

- `com.jaywapp.iamheadcoach`로 같은 Play App Signing 인증서 계보의 설치된 낮은 versionCode와 높은 versionCode 빌드가 있어야 한다. Preview와 자동 업데이트 호환성을 혼동하지 않는다.
- 테스트 계정이 앱을 소유하고 Play 트랙에 접근하며, 기기가 Google Play로 설치한 상태여야 한다. release sideload/debug/Preview에서는 업데이트 SDK를 호출하지 않는다.
- 기존 데이터는 .sq로 사용자가 백업한다. 문제 해결을 위해 삭제·초기화·강제 다운그레이드하지 않는다. 키 생성/교체/내용 조회나 기존 폰 설치는 이번에 수행하지 않았다.

## 폰 확인

1. 새 버전 안내에서 나중에/취소 선택 → 전술과 입력이 그대로이고 같은 버전 안내가 복귀마다 반복되지 않는지 확인한다. 수동 업데이트 확인은 다시 안내해야 한다.
2. 다운로드 동의 → 편집 계속, 오프라인/복귀/회전 후 진행·완료 안내 복구. 자동 재시작은 없어야 한다.
3. 다운로드 완료 → 저장되지 않은 전술 수정 → 저장 확인 후 재시작 → 전술·팀·선수·지침이 유지되는지 확인한다. .sq 복원→수정·저장→재시작 보존도 확인한다.
4. 저장 실패/활성 전술 없음/공유 열람/드래그·내보내기 중에는 설치 재시작을 막는지 확인한다. 대기 중 도움말을 닫아도 편집 잠금이 유지되고 실패 뒤에는 입력이 복구되어야 한다.
5. Preview 이름·아이콘·인트로·동작 줄이기·글자 확대·회전을 확인한다. Preview에는 릴리즈 정보 링크만 있고 Play/외부 APK 자동 설치가 없어야 한다.

증거: `.work/updates-feedback-20261014/device/`에 package/설치 versionCode/인증서 지문(공개 인증서만)/기기·OS/작업별 화면과 저장 복구 비교를 보관한다. 사용자 전술 내용·개인정보가 있는 증거를 Git에 추가하거나 외부로 업로드하지 않는다. 현재 폴더의 실제 기기 증거는 없다.

## 개인정보·Data safety 반영 준비

[공식 Play Core 데이터 안내](https://developer.android.com/guide/playcore/in-app-updates#data-safety)에 따르면 Play Core는 기기 메타데이터, 앱 버전, 설치 모듈/asset pack 목록 등을 수집하고 Google Play 서비스와 통신한다. 필요한 처리·전송은 로컬 전술 저장과 별개다. 실제 선택 SDK 버전을 개인정보처리방침/Data safety 초안에 대조하고 제출 전 확인해야 한다. 이번에 정책 공개 URL·스토어 양식을 제출하지 않았다.
