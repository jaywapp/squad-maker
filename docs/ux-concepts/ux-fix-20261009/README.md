# UX 구조 콘셉트 3종

orchestrator: Codex. 기존 A NightPitch의 차콜 그린, 초크 선택, 라임 주 행동과 IBM Plex Sans KR·Oswald, 버튼 10px·패널 16px를 유지하는 Operate 화면 비교다. 사용자 선택 전에 운영 `index.html`에 반영하지 않는다.

[갤러리](index.html) 또는 [로컬 갤러리](http://127.0.0.1:4320/index.html)에서 각 프로토타입을 연다. 로컬 URL은 root가 콘셉트 디렉터리만 공개한 preview 서버가 실행 중일 때 사용할 수 있다. 별도 빌드·패키지가 필요하지 않으며 HTML을 파일로 열거나 이 디렉터리만 공개하는 정적 서버에서 실행할 수 있다. Google Fonts를 사용할 수 없으면 기존 A 설계의 시스템 대체 글꼴로 표시한다. 시크릿·로그인·백엔드·실제 저장소를 읽지 않는다.

## 공통 데모

동일한 예시 `기본 팀 / 기본 전술 / 8vs8 / 3-3-1`, 골키퍼·수비1~3·미드1~3·공격1을 사용한다. 선수 선택은 피치와 목록에서 동기화된다. 위로·아래로 도구와 선수에 포커스한 방향키로 위치를 바꾼다. 선수 이름(12자), 선수 색상, 팀명을 수정한다. `내보내기`는 팀명이 피치 선과 분리된 실제 SVG 결과를 보여 주며, `PNG 다운로드`는 브라우저 캔버스로 대표 PNG를 생성한다.

결과물은 편집한 이름·색상·위치를 반영한다. PNG/SVG 선수 이름은 6자 초과일 때 앞 5자와 말줄임표로 표시한다. 예를 들어 `골키퍼테스트이름`은 `골키퍼테…`로 보이며, 전체 이름을 출력한다는 의미가 아니다. 편집 입력에는 최대 12자를 유지한다. 가로 이동은 세로 피치 좌표로 함께 환산한다. GIF는 인코딩하지 않는다. 이 PNG/SVG 결과는 각 GIF 프레임에도 적용할 수 있는 헤더·캡션 공간 설계 예시다. 실제 저장 계약 v2, 자동 저장, 파일 목록 CRUD, 움직임 패턴, 분석 이벤트, 네이티브 공유는 구현하지 않는다. 기본/공격/수비 버튼은 편집 상태 라벨만 전환하며 별도 좌표 세트를 저장하지 않는다. 데이터는 새로고침하면 초기화된다. 선수 끌기 대신 위치 도구와 방향키를 구현했다.

## 반응형 계약

- 1280px: 피치와 최소 320~370px 설정 열. 편집 데스크의 목록은 접힌다.
- 1920px: 고정 설정 열 340 / 320 / 370px, 남는 공간은 피치 주변으로 분배한다.
- 390px: 피치 아래 선택 도구, 팀 설정은 피치 스튜디오·매치카드에서 펼친다.
- 844×390: 가로 피치로 방향을 바꾸고 선택 도구를 옆에 둔다. 목록과 부가 지침은 접는다. 선택 도구의 높이가 커지면 해당 열만 스크롤한다.

## 스킬과 pre-flight

`impeccable`의 context·new-work·operate·craft-floor와 `design-taste-frontend` 및 pre-flight를 읽었다. 브리프 해석은 기존 브랜드 보존형 Operate 편집기다. DESIGN_VARIANCE=4/5/4, MOTION_INTENSITY=1/3/2, VISUAL_DENSITY=7/6/6으로 정했다. 각 모션은 도구 접근 또는 선택 피드백이다. reduced-motion은 모든 전환을 제거한다.

taste 스킬의 dense product UI 비대상 선언에 따라 랜딩 hero·사진·카드 개수·새 UI 패키지·이중 테마 요구는 이 기존 고정 다크 앱에 적용하지 않았다. 사용자와 기존 승인 설계가 정확한 3방향과 토큰을 지정했으므로 별도 init·브랜드 교체·무작위 콘셉트·AI 래스터 생성은 하지 않았다. 스킬이 제안하는 추가 DESIGN/PRODUCT 파일은 지정 파일 소유권 밖이므로 생성하지 않았다.

모든 버튼·입력은 최소 48px(가로 일부는 44px), 선수 탭 영역은 48px, 번호 원은 38px, 피치 이름은 12px다. 선택은 aria-pressed, 초크 바탕·굵기·테두리로 구분하고, 선수는 라임 링으로 구분한다. 키보드 포커스는 라임 3px, 내보내기는 native dialog로 Esc·포커스 제한을 브라우저에 맡긴다. 처리 중 잠금·PNG 오류·지속 결과 줄을 제공한다. 보이는 문구에 em dash를 사용하지 않았다.

## 실제 검증과 제한

콘셉트 담당의 `node --check`, HTML 중복 ID·em dash 정적 검사와 root의 최종 실제 확인을 완료했다. 최종 확인은 세 콘셉트 × 1280 / 1920 / 390 / 844×390 총 12개 화면, 결과물 3개, 실제 다운로드 PNG 3개다. 모든 화면에서 가로 넘침 0, 44px 미만 컨트롤 0, 앱 콘솔 오류 0이었다. native dialog Esc·열기 버튼 포커스 복귀와 선택 선수 이름 카운터도 통과했다. 1920 설정 열은 각각 340 / 320 / 370px다. 최종 수치는 [확인 기록](../../ux-fix-20261009/evidence/codex-20261009/concepts/confirmation/verification.json)에 있다.

골키퍼 색상 변경이 SVG와 실제 PNG에 반영됨을 확인했고, 가로에서 아래 이동을 반복해도 이름표가 피치 안에 남았다. 844×390 피치 하단은 콘셉트 01 y=385, 02 y=387, 03 y=386으로 모두 화면 높이 390 이내다. 모바일 Lighthouse 13.4.1 Accessibility는 세 콘셉트 모두 100이다: [01](../../ux-fix-20261009/evidence/codex-20261009/concepts/lighthouse/concept-01.json), [02](../../ux-fix-20261009/evidence/codex-20261009/concepts/lighthouse/concept-02.json), [03](../../ux-fix-20261009/evidence/codex-20261009/concepts/lighthouse/concept-03.json).

첫 배치에서 매치카드 가로 피치 하단 y=395가 화면을 넘었던 재현과 당시 증거는 [첫 검증 기록](../../ux-fix-20261009/evidence/codex-20261009/concepts/verification.json)으로 보존한다. 피치 높이 9px 보정, 가로 하단 경계 80%, 초기 가로 좌표 `100-y, x` 파생, 이름 카운터 동기화, 골키퍼 색상 출력 연결을 수정한 뒤 최종 확인했다. 코드는 이 확인 상태로 동결했다.

스크린샷은 Google Fonts를 의도적으로 차단한 시스템 대체 글꼴 렌더다. 첫 배치의 외부 글꼴 네트워크 오류는 fixture 오류로 별도 기록했고, 최종 앱 콘솔 오류는 0이다. 웹 글꼴이 실제 로드된 환경의 시각 차이는 이 증거에 포함하지 않는다.

미검증 또는 구현하지 않은 범위는 실제 Android·iOS 기기, 실제 운영 저장소 계약, 공유 앱을 통한 실사용, GIF 인코딩, 움직임 패턴·매치 전략 실제 동작이다. 기본/공격/수비 전환은 라벨 표현 데모이며 별도 배치 저장 기능을 입증하지 않는다. reduced-motion·글자 확대의 별도 실제 검증 수치는 이 콘셉트 보고에 없다. Lighthouse 점수는 수동 스크린리더 검사나 실기기 접근성 검증을 대신하지 않는다. 최종 콘셉트 선택 제시는 root가 담당한다.

운영 구현은 사용자 선택 후 새 작업계획으로 진행한다.
