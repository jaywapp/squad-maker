## 1. 요청

1. 수정 계획을 다섯 단계로 나눈다: 데이터 보호 → 편집·공유 동선 → 선택한 테마 적용 → Android·오프라인 검증 → 광고·결제·스토어 준비. 단계마다 문제, 변경 범위, 의존성, 완료 기준을 적고 필수 수정·시안 실험·후속 기능을 구분한다. 근거 없는 공수는 쓰지 않는다.
2. 실행 가능한 HTML/CSS/JS 시안 3종(A 나이트피치, B 데이라이트코치, C 택틱스스튜디오)을 같은 데모 상태로 만든다.
3. 360px·1366×768 렌더링 검증, 스크린샷, 실행 방법, 장단점, 검증·미검증 항목을 전달한다. 결과물은 아티팩트로 제공한다.
4. commit·push·PR·merge·배포를 하지 않는다. 사용자가 시안을 고르기 전에는 본 구현을 시작하지 않는다.

## 2. 현재 상태와 근거

시작 시점 저장소 상태: `main` 02c0af8, 원격과 같고 작업 트리에 변경 사항 없음. 이번 작업은 `docs/ux-redesign-20261007` 브랜치에서 문서와 시안 파일만 추가한다.

### 2.1 확정된 결함 (2026-10-07 독립 검토에서 화면으로 재현)

| ID | 문제 | 근거 |
|---|---|---|
| D1 | 인원 변경 시 지침이 없으면 확인 없이 선수 이름·세 스쿼드 배치·전술 패턴이 초기화되고 자동 저장으로 덮어써진다 | `onModeChange()` `index.html:1430`이 지침 존재만 확인. `initAllSquads()`가 로스터·스쿼드·패턴 재생성 |
| D2 | "↺ 초기화"가 확인·되돌리기 없이 현재 스쿼드 배치를 지운다 | `resetLayout()` `index.html:1642`에 `captureUndo` 없음 |
| D3 | `.sq` 불러오기가 확인 없이 덮어쓰고, 불러온 상태를 저장하지 않아 새로고침하면 이전 상태로 돌아간다 | `loadSquadFile()` → `applyState()` `index.html:3471`, `3540`에 `autoSave()` 호출 없음 |

### 2.2 재현이 더 필요한 항목

| ID | 문제 | 현재 판단 |
|---|---|---|
| R1 | 모바일에서 선수를 탭해도 선택 툴바가 열리지 않음 | Chromium 터치 에뮬레이션에서만 관찰했다. 원인 후보는 소스에서 확인했다(`touchstart`의 `preventDefault` `index.html:2015`). **실제 Android 기기 재현 전에는 확정 결함으로 다루지 않는다** |
| R2 | PNG·GIF 실패 시 피드백 없음 | PNG 생성 자체는 정상 동작했다. **확정 버그가 아니다.** 실패 경로에 사용자 메시지가 없다는 점만 소스로 확인했다 |
| R3 | 저장 실패를 조용히 무시 | `autoSave()`의 `catch {}`를 소스로 확인했다. 저장 공간 초과 같은 실제 실패 상황은 재현하지 않았다 |

### 2.3 정정·제외

- 모바일(≤500px)에서 개별 선수 지침 카드는 이미 기본 접힘 상태다(`index.html` init의 `playerNotesCard.open = false`). 이번 계획에서 별도 작업으로 잡지 않는다.

### 2.4 제품 방향 (사용자 제공, 현재 구현을 뜻하지 않음)

- Android 우선
- 1차: 로그인 없이 전술 편집, 기기 내 저장, PNG/GIF 저장·공유, 광고
- 무료 동시 저장 슬롯과 일회 결제로 영구 슬롯 확장. 삭제하면 슬롯을 재사용한다. 수정·자동저장은 제한하지 않는다
- 팀 = 프로젝트, 전술 = 파일. 슬롯의 정확한 단위는 미확정
- 2차: 광고 제거, 팀 공간에서 전술 공유·관리. 구독 방식 미정

## 4. 가정

- 1단계(데이터 보호)는 시안 선택과 무관하게 진행할 수 있는 필수 수정이다. 다만 이번 요청 범위가 계획까지이므로 구현은 사용자 승인 뒤에 한다.
- 시안은 계획 검토용 데모다. 실제 저장·내보내기·광고·결제·계정·분석을 연결하지 않는다.
- 저장소는 정적 단일 파일 앱이다. 동적 데이터·인증이 없으므로 Supabase는 이번 범위에서 제외한다(2차 팀 공간에서 다시 검토).
