# UX 개편 계획과 시안 3종: 설계

- slug: `ux-redesign-20261007` · [분석](ux-redesign-20261007-analysis.md) · [작업](ux-redesign-20261007-tasks.md)
- 상태: blocked (사용자 시안 선택 대기). 아래 계획 중 운영 코드 변경은 사용자 승인 전까지 시작하지 않는다.

## 1. 구분 기준

| 구분 | 뜻 |
|---|---|
| **필수 수정** | 확정 결함이나 데이터 손실을 막는 변경. 테마 선택과 무관하다 |
| **시안 실험** | 선택된 시안에 따라 형태가 달라지는 변경. 사용자 선택 뒤에만 진행한다 |
| **후속 기능** | 제품 결정(슬롯 단위·가격·배포 방식)이 필요한 변경. 결정 전에는 자리와 데이터 구조만 준비한다 |

공수는 근거가 없어 적지 않았다. 각 작업의 크기는 착수 시 해당 단계 tasks에 실제 변경 파일과 함께 기록한다.

## 2. 단계별 계획

### 1단계. 데이터 보호 (필수 수정)

| 항목 | 내용 |
|---|---|
| 문제 | D1 인원 변경 시 이름·배치·패턴 손실, D2 초기화 되돌리기 없음, D3 `.sq` 복원 후 저장 누락과 확인 없는 덮어쓰기. R3 저장 실패 무음 |
| 변경 범위 | `onModeChange()`: 확인 조건을 "기본값과 다른 사용자 변경 존재"로 넓히고 사라지는 대상을 문구에 적는다. 변경 직전 `captureUndo()`, 직후 `showUndoToast()`. `resetLayout()`: `captureUndo()`와 되돌리기 토스트. `loadSquadFile()`: 덮어쓰기 확인 → `captureUndo()` → `applyState()` → 즉시 저장 → "복원하고 기기에 저장했습니다 · 되돌리기". `autoSave()` 실패 시 닫히지 않는 경고와 백업 받기 버튼. 후속으로 인원 변경 시 기존 이름·색을 순서대로 유지하는 안 검토 |
| 의존성 | 없음. 테마 선택(Q1)과 무관하게 먼저 진행할 수 있다. 기존 되돌리기 장치(`captureUndo`/`restoreUndo`/`showUndoToast`)를 재사용한다 |
| 완료 기준 | 아래 시나리오가 `tests/`의 회귀 테스트(390px·1280px)로 자동 검증된다. ① 이름만 바꾼 상태에서 인원 변경 → 확인창 → **취소** 시 상태 그대로 ② **확인** 후 되돌리기 → 이름·세 스쿼드 배치·패턴 복원 ③ 되돌리기 후 **새로고침**해도 복원 상태 유지 ④ 아무것도 바꾸지 않은 첫 화면은 확인 없이 변경 ⑤ 초기화 → 되돌리기 → 새로고침 후 유지 ⑥ `.sq` 불러오기 확인 **취소** 시 현재 상태 유지, **확인** 후 새로고침해도 불러온 상태 유지, 되돌리기로 이전 상태 복원 ⑦ localStorage 쓰기 실패를 주입하면 경고가 보인다. 기존 회귀 스펙(`guest-free-regression` 등) 모두 통과 |

### 2단계. 편집·공유 동선 (필수 수정 + 시안 실험)

| 항목 | 내용 |
|---|---|
| 문제 | 저장·백업·내보내기·공유 버튼이 세 곳에 흩어져 있다. "파일 저장"이 `.sq`와 `.txt` 두 의미로 쓰인다. 내보내기 성공·실패 피드백이 없다. 데스크톱 1440×900에서 선택 툴바가 첫 화면 밖에 뜬다. 모바일 탭 선택 문제(R1)는 실기기 재현이 필요하다 |
| 변경 범위 | **필수**: 버튼 이름 정리("백업 파일 받기(.sq)", "백업에서 복원", "텍스트 파일로 받기"), PNG·GIF 성공·실패 토스트, GIF 진행 중 취소와 실패 시 오버레이 닫기, 저장 상태 표시("이 기기에 저장됨"). **R1**: 실제 Android Chrome에서 재현되면 `touchend`에서 이동 8px 미만·길게 누르기 전이면 선택하도록 고친다. 재현되지 않으면 원인을 기록하고 닫는다. **시안 실험**: 내보내기·공유를 하나의 시트(이미지·GIF / 링크·텍스트 / 백업)로 모으는 구조, 선택 도구 위치, 데스크톱 피치 높이 맞춤은 선택된 시안의 배치를 따른다 |
| 의존성 | 1단계 완료(복원·되돌리기 동작이 시트 안 "백업에서 복원"에 쓰임). 시안 실험 항목은 Q1 답변. R1 수정은 실기기 재현 결과. 공유 1순위(Q5)에 따라 시트 안 순서 결정 |
| 완료 기준 | ① 처음 쓰는 사용자 과제 "이 전술을 단톡방에 이미지로 올려 보세요"를 시안 프로토타입이나 구현본에서 관찰하고 잘못 누른 버튼을 기록한다 ② 360×800, 1366×768, 1440×900에서 피치와 선택 도구가 스크롤 없이 함께 보인다 ③ 내보내기 성공·실패·취소 각각에 사용자 메시지가 있다(실패는 네트워크 차단으로 주입) ④ 실제 Android 기기에서 탭→선택, 드래그→이동, 길게 누르기→메뉴를 확인한다 ⑤ 1단계 회귀 테스트 계속 통과 |

### 3단계. 선택한 테마 적용 (시안 실험)

| 항목 | 내용 |
|---|---|
| 문제 | 라임 강조색이 6곳 이상에 쓰여 주 행동이 흐리다. 선수 이름 10.4px, 보조 텍스트 대비 부족(버전 표기 약 4.3:1 추정), 주요 탭 40px·입력 32px로 48px 목표 미달. 피치 라인·페널티 스폿이 이름과 겹친다 |
| 변경 범위 | 선택된 시안의 토큰(색·글꼴·간격·모서리)을 `:root` 변수로 옮기고, 화면 구조를 시안대로 바꾼다. 선수 라벨 배경, 터치 영역 48px, 대비 AA, 포커스 표시, `prefers-reduced-motion`을 함께 적용한다. 공유 텍스트·내보낸 이미지의 표현도 같은 테마로 맞춘다 |
| 의존성 | Q1(시안 선택) 필수. 1·2단계 완료. 저장소 규칙상 선택 결과와 피드백을 분석·설계 문서에 먼저 기록 |
| 완료 기준 | ① 360/412/1366/1440 너비에서 가로 넘침 0 ② 본문 텍스트 대비 4.5:1 이상, 큰 텍스트 3:1 이상(자동 측정) ③ 주요 터치 영역 48px 이상(측정 스크립트) ④ 키보드만으로 선수 선택·이동·내보내기 시트 열기·닫기 가능 ⑤ 기존 회귀 테스트 통과, 스냅샷 `v:1` 계약 유지 |

### 4단계. Android·오프라인 검증 (필수 수정 + 후속 기능)

| 항목 | 내용 |
|---|---|
| 문제 | html2canvas를 제작자 도메인에서, gif.js와 워커를 cdnjs에서 런타임에 불러온다. 경기장처럼 네트워크가 약한 곳에서 내보내기가 실패할 수 있다(추정). 실제 Android 기기 검증 이력이 없다 |
| 변경 범위 | **필수**: 내보내기 라이브러리를 저장소에 포함해 오프라인에서도 동작하게 한다(테스트는 이미 `tests/vendor` 고정 버전을 사용). 실제 Android 기기 점검표(Chrome, 가능하면 Samsung Internet): 탭·드래그·길게 누르기, 소프트 키보드가 피치를 가리는지, 다운로드 위치, 공유 시트, 저장 유지. **후속**: 배포 방식(Q4)에 따라 PWA 매니페스트·서비스 워커 또는 앱 래퍼 구성 |
| 의존성 | 1·2단계(검증 대상 동작). Q4는 후속 항목에만 필요 |
| 완료 기준 | ① 네트워크를 끊은 상태에서 PNG·GIF 내보내기 성공 ② 실제 Android 기기 1대 이상에서 점검표 전 항목 결과 기록(기기·OS·브라우저 버전 포함) ③ 앱을 완전히 종료했다가 다시 열어도 작업이 유지된다 |

### 5단계. 광고·결제·스토어 준비 (후속 기능)

| 항목 | 내용 |
|---|---|
| 문제 | 광고·슬롯 결제·스토어 출시가 제품 방향에 있지만 슬롯 단위(Q2), 수량·가격·시점(Q3), 배포 방식(Q4), 광고 정책(Q6)이 정해지지 않았다 |
| 변경 범위 | 결정 전: 광고 자리 예약(편집 화면 밖, 내보내기 결과 아래, 전술 목록의 고정 칸)과 레이아웃 이동 방지 높이 확보, 슬롯 개수를 데이터에서 셀 수 있는 저장 구조 검토(현재 단일 `squad-maker-v1` 키). 결정 후: 광고 SDK 연동, 결제(Android 앱이면 Play 결제), 개인정보처리방침·데이터 안전 섹션·스토어 등록 정보 |
| 의존성 | Q2·Q3·Q4·Q6 답변. 3단계 테마 확정(광고 자리 디자인). 4단계 Android 검증 |
| 완료 기준 | ① 광고 자리가 피치·편집 도구·내보내기 버튼·되돌리기 토스트와 24dp 이상 떨어져 있다 ② 편집 중 화면에는 광고가 없다 ③ 슬롯이 가득 찬 상태에서 삭제하면 바로 재사용되고 수정·자동저장은 막히지 않는다 ④ 결제·광고는 스토어 정책 검토 결과를 문서로 남긴 뒤에 켠다 |

## 3. 시안 3종 설계

공통 조건: 같은 데모 상태(`shared/state.js`, 우리 FC / 9v9 / 3-3-2, 선수 9명, 전술 3개)를 각 파일에 그대로 넣었다. 실제 저장·광고·결제·계정·분석은 연결하지 않았고, 저장됨·처리 중·실패·되돌리기 상태에는 "시안" 표시를 붙였다.

| 안 | 방향 | 레이아웃 | 조작 방식 |
|---|---|---|---|
| A 나이트피치 | 현재 정체성(다크 그린·라임·Oswald)을 다듬는 안 | 피치가 화면 대부분, 위쪽 얇은 바 | 선택하면 편집 도구가 나타남 |
| B 데이라이트코치 | 밝은 고대비, 큰 글자, 야외 사용 | 선수 → 배치 → 움직임 단계형 흐름 | 목록과 "다음" 중심의 안내형 |
| C 택틱스스튜디오 | 네이비·코발트, 팀=프로젝트·전술=파일 | 파일 탐색 + 피치 + 속성 패널, 하단 타임라인 | 키프레임 타임라인으로 단계 편집 |

광고 자리는 세 안 모두 피치·편집 도구 밖에 두었다. 기존 `ad-placement.md`의 "공유 모달 안 광고(P2)"는 복사 버튼과 가까워 시안에서는 쓰지 않았다(Q6).

## 4. 검증 전략

- 시안: Playwright로 360×800(터치 에뮬레이션)과 1366×768을 렌더링하고, 가로 넘침·피치와 선택 도구 동시 노출·텍스트 대비·포커스 표시·48px 목표를 스크립트로 측정한다. 실제 Android 기기 검증이 아니다.
- 본 구현(승인 뒤): 단계별 완료 기준을 `tests/`의 Playwright 회귀 테스트로 추가하고, 실제 Android 기기 점검표는 4단계에서 사람이 수행한다.

## 5. 보안·호환성

- 시안은 외부 스크립트를 쓰지 않고 Google Fonts만 불러온다. 데모 데이터에 개인정보가 없다.
- 본 구현은 스냅샷 `v:1`과 공유 URL `#s=`·`.sq` 형식을 유지한다. 슬롯 구조를 바꿀 때는 마이그레이션과 `sanitize*` 검증을 함께 추가한다.
