# Run Line APK 백업·설치 안내

사용자 직접 설치용이다. APK 생성/서명 검증과 휴대폰 검증은 구분한다. 실제 source SHA·APK SHA256·버전·공개 인증서 비교 결과는 PR #47과 로컬 `.work/branding-apk-20261008/build-verification.json`에서 확인한다.

## 설치 전 백업

1. 기존 Preview에서 저장 상태가 완료인지 확인한다. 오류/blocked가 있으면 설치를 멈추고 상태를 기록한다.
2. 팀/전술 목록에서 모든 보관 파일을 하나씩 연다. `내보내기·공유`의 **백업 파일 저장(.sq)**로 휴대폰의 앱 외부 폴더에 저장한다. 팀명·전술명과 구분되는 이름을 쓰고 파일이 실제 존재하며 크기가0이 아닌지 확인한다. 가능하면 PC에도 복사한다.
3. 보관 목록/팀·파일 이름·파일 수·현재 선택을 스크린샷 또는 메모로 남긴다. 중요한 전술의 선수·기본/공격/수비 위치·노트·패턴도 비교용으로 기록한다. 개인정보가 있는 백업/화면은 PR에 올리지 않는다.
4. `.sq` 하나는 현재 전술의 편집 원본이며 library 전체 목록/팀명/선택의 일괄 백업이 아니다. 모든 파일을 백업해야 한다. PNG/GIF와 공유 링크만으로 백업을 대신하지 않는다. 이 앱은 Android 자동 backup을 꺼 놓았으므로 Google 백업 완료를 가정하지 않는다.

## APK 확인과 업데이트 설치

1. PC의 `.work/artifacts/squad-maker-0.1.0-preview.2.apk`를 준비한다. `Get-FileHash -Algorithm SHA256 -LiteralPath '<APK 절대경로>'`로 인계한 SHA256과 같은지 확인한다. 인증서 지문과 파일 SHA256은 서로 다른 값이다.
2. 기존 앱이 `com.jaywapp.squadmaker.preview`의 Preview1001/0.1.0-preview.1이며 이전 GitHub Preview에서 설치한 앱인지 확인한다. 다른 package/인증서 또는 더 높은 versionCode가 의심되면 설치를 보류한다. 실제 설치 APK의 인증서는 이 세션에서 확인하지 못했다.
3. APK를 USB/개인 파일 전송으로 휴대폰에 복사한다. 해당 파일 관리자에서 APK를 열고 OS의 **업데이트**를 선택한다. 필요할 때만 그 파일 관리자에 알 수 없는 앱 설치를 허용하고 끝나면 해제한다. 기존 앱을 먼저 삭제하거나 데이터/저장공간을 지우지 않는다.
4. 선택적으로 사용자가 직접 `adb -s <본인기기> install -r '<APK 경로>'`를 실행할 수 있다. `-d`, uninstall, clear는 사용하지 않는다. 이 세션은 연결/설치 명령을 실행하지 않는다.
5. 앱이 설치되지 않음·서명 충돌·버전 다운그레이드 오류가 나오면 중단하고 오류/기존 버전만 전달한다. 삭제 설치로 해결하지 않는다. 설치 후 데이터가 다르면 새 편집/초기화/일괄 가져오기로 덮지 말고 원본 백업과 상태를 보존한 채 알린다.

모델·Android 버전·런처·설치 전/후 버전과 위5개 결과를 기록한다. 전체 [T7 10개 체크리스트](brand-run-line-pr-20261008-t7.md)의 추가 항목도 실제 확인 전에는 미검증이다. 에뮬레이터 결과는 별도 표시하며 물리 기기 결과로 대신하지 않는다.

휴대폰 설치/공개 Release/main 병합은 이 세션에서 수행하지 않았다. PR은 Draft, 자동 배포는 중단 상태다.
