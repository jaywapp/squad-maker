# 편집 데스크 운영 적용 설계

## 확정 방향

사용자가 선택한 [① 원본](ux-concepts/ux-fix-20261009/concept-01/index.html)을 기존 A NightPitch 운영 화면에 적용한다. Operate 편집기이며 native CSS/기존 토큰을 사용한다. DESIGN_VARIANCE=4, MOTION_INTENSITY=1, VISUAL_DENSITY=7. 랜딩 사진·새 컴포넌트 패키지·브랜드 교체·초기화는 필요 없다.

`impeccable`의 기존 context 결과와 adapt/craft-floor, `design-taste-frontend`의 preserve/pre-flight를 적용한다. 선택 전 콘셉트 검증은 완료됐다. 시각 확인은 데스크톱·모바일을 묶은 첫 배치→한 번의 보정 배치→확인으로 제한하고, 기능 회귀 실패의 필수 보완은 별도로 기록한다.

## 레이아웃

- 대형 화면: 실제 전술/선수 목록 220px / 유동 피치 / 최소 340px 설정. 별도 280px 선수 도구 열을 없애 기존 `#playerActions`를 설정 쪽에 둔다. 파일 CRUD는 기존 library sheet에서 처리하고 목록의 파일 열기는 기존 계약을 사용한다.
- 1280: 왼쪽 목록을 접고 피치와 설정 2열. 목록은 기존 파일 제목 버튼으로 계속 접근한다.
- 390: 기존 피치·선택 트레이·팀 설정/지침 접근을 유지한다.
- 844×390: 헤더를 압축하고 수평 피치 / 선택 도구 2열을 만든다. 부가 설정은 오른쪽 영역에서 스크롤하며 접근할 수 있다. 숨겨서 기능을 없애지 않는다. safe-area·44px 터치·긴 이름·포커스는 유지한다.
- 패턴은 피치와 실제 경로/재생 도구를 연결한다. 전략은 기존 피치 비표시 흐름을 유지한다. 뷰어에는 편집 목록·선수 도구를 노출하지 않는다.

## 화면 투영과 저장

논리 필드는 항상 W=480,H=660다. 수평 화면의 투영은 `T(x,y)=(660-y,x)`, 역변환은 `T^-1(X,Y)=(Y,660-X)`이며 화면 논리 크기는660×480이다. 화면 배율은 화면 폭으로 나눈다. DOM/캔버스·포인터·드래그·키보드가 같은 투영 규칙을 사용한다.

방향키는 화면 방향을 기준으로 한다. 수평 ArrowRight는 논리 `(0,-8)`, ArrowDown은 `(8,0)`이다. Shift 이동32·경계·최근 실제 이동의 undo·자동 저장을 유지한다. 진행 제스처가 없는 resize/방향 전환은 렌더만 변경한다. 진행 중 미완료 드래그는 기존 취소 의미에 맞춰 시작 위치로 복구하고 저장·undo·선택을 추가하지 않는다. 미완료 패턴 경로는 추가하지 않는다. 이미 완료한 이동은 되돌리지 않는다. 선수 번호·이름은 화면에서 똑바로 표시하고 실제 이름12px/번호19px, 기존 색 대비·hit radius를 보존한다. inline rename·선택·메뉴도 방향 전환 후 정상 작동한다.

## PNG/GIF 출력

내보내기는 화면 방향과 무관하게 기존 세로 논리 피치480×660을 사용한다. 기본 상단 헤더 높이는72px, 총 논리 출력480×732다. 실제 팀명(없으면 기존 스쿼드 fallback), 상태/포메이션·패턴/단계 정보를 읽을 수 있게 배치하고 피치 바깥에서 그린다. 긴 팀명은 출력에서 폭에 맞춰 줄이되 원본 데이터는 유지한다.

PNG는 live 피치의 폭/회전/선택 상태를 변경하지 않는 export 전용 세로 장면을 사용한다. 기존 html2canvas·deliverExport·MIME·파일명·busy/timeout/finally 경계를 보존한다. GIF는 별도 헤더 공간에 팀명/단계 정보를 그리고 기존 renderStepFrame의 피치를 아래에 합성한다. 프레임 수·delay·이동/공 경로·single/all 정책·재생 중지/복구·worker/watchdog·분석 이벤트를 유지한다. 저수준 프레임의 좌표와 데이터 FIELD_H를732로 바꾸지 않는다.

PNG 전용 장면은 live 필드가 pattern/strategy에서 숨겨져 있어도 독립적으로 표시한다. 헤더의 배경색만 있는 파일을 성공으로 오인하지 않도록 실제 출력의 선수 색 픽셀을 검사한다. 진행 드래그 중 완료된 변경의 autosave 예약은 보류하고 완료·취소 뒤 재개한다. blur/hidden/pagehide에서는 미완료 좌표를 복구하고 waiter를 해제한 뒤 일반 라이브러리/CAS 저장을 수행한다. 이름표가 다른 선수의 원 위에 겹쳐도 가로 선수 원의 입력은 통과하며 circle 더블클릭·선택 도구·키보드 이름 편집을 유지한다.

패턴 방향 요약과 선수 이동 퍼센트 안내도 화면 투영 기준으로 표현한다. GIF는 단계당 기존 실제39프레임과 delay를 유지하며 기존 진행률 분모 보정 같은 별도 변경을 섞지 않는다.

## 검증

기존 전체 단위/desktop/mobile E2E를 workers1/retries0으로 새로 실행한다. 신규 회귀는 1920 설정 폭·실제 목록 열기/뷰어 보호,844×390mouse/touch/keyboard/rotation 저장 보호,패턴의 수평 경로,PNG/GIF 헤더 및실제 내려받기,실패/취소 복구를 포함한다. 기존 테스트의 기대 동작을 약화하지 않는다.

실측·Lighthouse·detector·PNG/GIF 프레임 증거는 `docs/editing-desk-20261010/evidence/`, 전체 로그와 임시 서버/테스트 설정은 ignored `.work/editing-desk-20261010/`에 둔다. 로컬 서명·실기기 설치·공개 배포는 실행하지 않는다. 기존 native 코드·의존성·workflow diff는 없어야 한다.


## 최종 출력 앵커와 측정

PNG 전용 원은44×44 고정이며 transform 없이 `(x−22,y−22)`에 배치한다. 실제 색 픽셀 중심을 `(x×2.5,(y+72)×2.5)`와 비교해 이름 길이/골라인 분기의 좌표 중복 해석을 검출한다. 가로 배율은 목표 폭에서 직접 계산하고 settled rAF는 재예약하지 않으며 진행 drag에서는 fit를 적용하지 않는다. 새 선수 목록은 number/name 콘텐츠에서 접근성이름을 계산해 표시 문구와 일치시킨다. 최종 검증과 잔여 이름표 제약은 report에 기록한다.
