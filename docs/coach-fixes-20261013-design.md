# 코치 사용성 오류 수정 설계

## 전술 내용

지침서의 본문·복사·텍스트 파일에는 감독이 입력한 팀/개인 지침, 경기 메모, 실제 패턴 움직임을 넣는다. 좌표로 추정한 자동 문장은 별도 접힌 ‘자동 제안’으로 표시하고 공식 전달문에서 제외한다.

## 패턴 시작 위치

v1 패턴에 선택적 `start: { squad, pos }`를 추가한다. 새 빈 패턴은 처음 패턴을 사용할 때 현재 배치를 고정한다. 저장·공유·복원·GIF 모두 고정된 좌표를 사용한다. 기존 데이터에 필드가 없으면 그 스냅샷의 선택 스쿼드로 정규화한다. 기존 v1 버전과 구형 단일 단계 형식을 유지한다. 새 필드를 이해하지 못하는 과거 배포본은 고정 출발점을 보장하지 못하므로 이번 검증은 수정본 수신 화면 기준이다. 이미 고정된 패턴 탭을 열 때는 추가 자동저장을 예약하지 않는다.

## 재생

단일 requestAnimationFrame 시간축에서 단계 이동·단계 간 정지를 처리한다. 일시정지 시 경과 시간·현재 단계·진행률을 유지한다. 이어 재생과 처음부터 재생을 구분한다. 패턴/단계 변경, 편집, 탭 이동 때 이전 재생을 정리한다.

## 공유

공유 URL에만 선택적 `view: { mode, pattern, step }`를 추가한다. 수신자는 유효한 범위로 제한한 장면을 열며 기존 로컬 저장은 바꾸지 않는다. 공유 장면은 배치 또는 패턴의 선택 단계 시작점이며, 애니메이션 중간 프레임·전략 생성 화면은 저장하지 않는다. 구형 링크는 배치·첫 패턴·첫 단계로 열린다. 공유 매개변수가 있지만 해석에 실패하면 편집기를 감추고 오류 안내 및 내 전술로 돌아가기만 제공한다. 이 상태에서 저장·가져오기·출력을 막고 저장소 초기화도 생략한다.

공유 URL 상자는 레이블이 있는 읽기 전용 textarea로 바꾼다. 복사가 불가능하면 해당 문자열만 선택하고 수동 복사를 안내한다. 클립보드 API 자체가 없는 환경도 같은 경로로 처리한다.

## 검증

새 회귀 테스트와 기존 관련 E2E를 데스크톱 1280×800·모바일 390×844에서 실행한다. 저장 구조 변경 때문에 구형 v1·단일 단계·선수 추가/삭제·백업 복원도 확인한다. 단위 테스트와 Android 웹 번들 빌드를 실행한다. 브라우저 화면과 실제 GIF 출력을 확인한다. 외부 서비스 배포는 없다.

## 승인된 Git 통합

사용자의 후속 승인에 따라 기존 브랜치에 Conventional Commit을 만들고 일반 push한다. PR #54의 최종 설명을 전체 변경에 맞추고 base를 main으로 변경해 병합한다. PR #52의 선행 커밋은 현재 HEAD의 조상이므로 별도 병합 없이 포함된다. 병합 직전 head SHA·충돌·원격 정책을 확인하고 merge commit 방식으로 통합한다. 이전 CI 성공을 새 커밋의 CI 성공으로 표시하지 않으며, 비활성화된 검증·배포 워크플로를 재활성화하지 않는다.
